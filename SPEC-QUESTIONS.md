# Questions about the specification

Found while building the file layer on 2026-11-16, against `VRMXA-base-draft.md` 0.26,
`VRMXW-base-draft.md` 0.10, `CLOSET.md` 0.4 and `EDITS.md` version 7. Each entry says where, what
is unclear, a proposed wording, and what this library does now. Where there was a choice, the
reading that keeps a plain VRM export working was taken.

**All 20 decided 2026-11-16, as proposed**, and written into `VRMXA-base-draft.md` 0.27,
`VRMXW-base-draft.md` 0.11 and `EDITS.md`. The real choices became decisions D29 (#2, #3: the
schema is exact, a newer one is skipped), D30 (#7, #8: the database is optional, the thumbnail
expected), D31 (#16: shared size defaults), W15 (#18: `x-<vendor>.<name>` types) and W16 (#4:
dangling parts skinned to their own spring bones). #5 took the first option: `origin` added to
VRMXA §7.4, `source` and `thumbnail` to VRMXW §12. The rest are the proposed wordings. The
library follows every decision; the "What the library does" column below is as it now stands.

## Phase 4: items and the importer (2026-11-16, decided)

Found while building `src/import/` (the importer), `src/item/` (the item editor and the four steps) and their
screens, and while importing Elena and VRoid models from the dataset. None is edited in the specification here.

**All ten decided 2026-11-17, as recommended**, and written into `VRMXW-base-draft.md` 0.14 as W17 to W26 (#37 is
W17, #38 W18, and so on to #46, W26; vrmxa-spec 568280a and aaf4475). What changed in the library:
- #37 (W17): `origin.sha256`, `fit` (`spec-fit`, `bones` or `four-steps`), `lift` and `converted` (true or false)
  are known keys; the checker gives a warning, never an error, for a wrong type. The importer writes `converted` as
  true or false and the four steps write `fit: "four-steps"`. The other keys (`vrm`, `pieces`, `importer`,
  `makerFrom`) stay as unknown keys.
- #38 (W18): `bodyAccessory` is a standard type (slot `accessory`, kind `worn`, fit by `bones`); the importer
  proposes it. A vendor's worn accessory type now takes its defaults.
- #41 (W21): **behaviour changed.** The donor body's own secondary bones (any non-humanoid joint the body skin
  leans on; VRoid's `J_Sec_*_Bust` always) are folded into their humanoid ancestor; their spring chains are not
  carried. Elena's dress has lost its two Bust chains and keeps its 30 skirt chains.
- #44 (W24): **format changed.** A state's `show` names meshes by node `name`; in an item that has states, names
  are unique (the writer makes them so in every item; the checker gives an error for a repeated name in an item
  with states, or a `show` name no mesh has). An older item's node indices are read as names with a note
  (`item.show-index`). New fixtures: `items/state-parts.vrmxw` and `legacy/show-by-index.vrmxw`.
- #46 (W26): `origin.headScale` is a known key, a positive number; the checker warns on a wrong type. The library
  already moved and scaled what the head carries.
- #39 (W19), #40 (W20), #42 (W22), #43 (W23), #45 (W25): no change; the library already did as decided.
